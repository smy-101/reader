# Spec: S4 跨书对比 —— 全库纯向量多书检索 + 跨书会话(书库页全局入口)+ D-33 悬空引用降级

Status: ready-for-agent
Created: 2026-08-29
Source: `docs/需求文档.md` v1.3(S4 场景与 D-36、FR-104/D-33、FR-303/304、FR-403、§9 待定项)+ `CONTEXT.md` 术语表(跨书会话/引用/向量块)+ M4 落地现状
Milestone: M4 收尾件(M4 spec 承诺的 mini-spec;S4 在需求文档中为 M4 可选项,本轮动工)

## Problem Statement

作为个人读者兼开发者,M4 之后单本书已经能"问 AI 作者在哪讨论过 X"并跳回原文了,但读书人的另一类问题没有通路:"这两本书对同一个问题怎么看?""我的书库里还有哪些书讨论过这个主题?"——现在的 AI 只能看到当前打开的那一本书,跨书比较要靠自己开两个窗口人肉对照。同时,会话域目前是纯书级的:提问端点挂在书下、会话路由只认书属会话、检索按单书过滤且命中不带书身份;跨书会话(不挂书的会话)虽然在 schema 里预留了可空 book_id,却没有任何入口能创建它,也没有任何行为围绕它工作。最后,需求文档 D-33 承诺的"跨书会话不随书删除级联、引用降级为'原书已删除'占位"至今只是迁移脚本里的一行注释,未兑现。

## Solution

在书库页提供全局「AI 伴读」入口(§9 决议:书库页全局入口,本轮已与用户确认):打开一个跨书会话面板,与阅读器内 AI 面板同构——会话列表 + 消息流(含引用条)+ 输入框 + 重命名/删除。在这里提问,后端把问题向量化后在**全库**做纯向量检索(D-36,§9 决议:全库自动,已与用户确认):自动覆盖所有"嵌入完成且嵌入模型与当前配置一致"的书,未就绪的书静默排除;按相关度取 top-k,块带〔书名·章节〕溯源装配进 prompt。回复照常 SSE 流式渲染,引用条随开场元数据事件在流式开始前可见,携带可点击的跨书引用(书名 + 章节标题 + 原文摘录);点击引用打开对应的书进入阅读器,复用 S3 跳转口径定位到章节并尽量命中摘录文字。跨书会话不挂书、不随任何书删除级联;书被删后,历史引用降级渲染为"《书名快照》(原书已删除)"占位且不可跳转。未配置 embedding 或全库没有一本就绪书时,入口隐藏(FR-403)。自动化中 embedding 与 chat 一律 OpenAI 兼容 stub 替身、向量确定性;真实跨书检索质量走人工验收。

## User Stories

1. As a reader, I want 在书库页有全局「AI 伴读」入口, so that 不打开任何一本书也能就整个书库提问(S4)。
2. As a reader, I want 未配置 embedding 时看不到这个入口, so that 功能优雅隐藏而不是点了报错(FR-403)。
3. As a reader, I want 全库没有任何一本嵌入完成的书时入口同样隐藏, so that 不会进入一个只会报错的面板。
4. As a reader, I want 配好 embedding 且至少一本书嵌入完成后入口自动出现, so that 门槛过了能力自然亮起。
5. As a reader, I want 问"A 书和 B 书对 X 的看法有什么不同", so that 得到跨书的对比式回答而非单书视角(S4 核心价值)。
6. As a reader, I want 检索自动覆盖全库所有就绪的书, so that 不用手工圈范围、也不会漏掉忘了的书(§9 决议:全库自动)。
7. As a reader, I want 未嵌入完成或模型已更换的书静默排除在检索外, so that 不用先整理全库嵌入状态才能提问。
8. As a reader, I want 回复照常流式渲染, so that 体验与 S1/S2/S3 完全一致(FR-303 / D-25)。
9. As a reader, I want 回复携带跨书引用(书名 + 章节标题 + 原文摘录), so that 对比结论可回溯到具体书的具体位置。
10. As a reader, I want 引用条在流式开始前即可见(随开场元数据事件), so that 一边等答案一边就能看出它引了哪几本书。
11. As a reader, I want 点击引用打开对应的书并定位到章节、尽量命中摘录文字, so that 从对比结论一步回到原文(复用 S3 跳转口径)。
12. As a reader, I want 引用指向"当前没在读的那本书"时跳转同样正常, so that 跨书跳转是真的跨书。
13. As a reader, I want 跨书会话可重命名、可删除, so that 会话管理体验与书级会话一致(FR-304)。
14. As a reader, I want 提问自动落入最近活跃的跨书会话(无则新建), so that 不用每次手动建会话(D-32 精神)。
15. As a reader, I want 刷新/重开面板后会话、消息与引用都还在, so that 讨论可续(refs 持久化)。
16. As a reader, I want 跨书会话不出现在任何单本书的 AI 面板里, so that 两种语境不打架。
17. As a reader, I want 删除某本书后跨书会话原样保留, so that 围绕多书的讨论不因一本书消失而消失(D-33)。
18. As a reader, I want 书删除后历史引用显示"《书名》(原书已删除)"占位且不可点击, so that 讨论脉络仍可读、不会点进死链(D-33)。
19. As a reader, I want 提问中途出错看到显式错误而不是永久转圈, so that 界面永不悬挂(FR-303)。
20. As a reader, I want 面板开着时全库就绪状态变化(如嵌入完成、模型更换)后重开面板即收敛, so that 显隐与可用性不需要推送也终会正确(v1 无推送,与 D-44 口径一致)。
21. As a reader, I want 桌面端(壳内即 Web)拥有同样的跨书能力, so that 不用记哪个功能在哪个端(§3.3 矩阵)。
22. As an API consumer, I want 跨书提问端点与书级提问端点契约同构(SSE:meta → delta… → done/error,citations 随 meta 下发), so that 前端复用同一套流式消费代码。
23. As an API consumer, I want 跨书会话列表 / 消息 / 重命名 / 删除端点, so that 面板四件事齐全,其中消息/重命名/删除复用现有会话端点。
24. As an API consumer, I want 引用(refs 与 citations)携带书标识与书名快照, so that 前端能渲染跨书引用、跳转,并在书删除后靠快照降级占位。
25. As an API consumer, I want 书库列表项带嵌入就绪摘要, so that 入口显隐与状态卡一次拿齐、不用逐书轮询拼判断。
26. As an API consumer, I want 跨书提问前置不满足(未配置 embedding / 全库无就绪书)返回可读中文文案, so that 前端能准确引导而不是裸 500。
27. As an API consumer, I want 显式指定会话时校验其为跨书会话, so that 书级会话与跨书会话不会被串线。
28. As an API consumer, I want 新端点不带/带错 token 一律 401, so that 安全边界与 M0–M4 完全一致。
29. As a developer, I want 检索查询从"单书过滤"泛化为"书集合过滤"(空集=全库)且命中携带书身份, so that S3 单书与 S4 多书共用一条查询路径,不养两份 SQL。
30. As a developer, I want 跨书 prompt 装配复用既有检索装配与预算口径(份额贪心 + token 近似计数), so that 不发明第二套预算逻辑。
31. As a developer, I want packages/api-client 扩展跨书端点类型与引用书字段, so that 前后端契约单一出处、桌面壳零改动。
32. As a developer, I want 自动化里 embedding 与 chat 一律 OpenAI 兼容 stub 替身且向量确定性, so that 多书检索排序可断言、CI 零新增外网依赖。
33. As a developer, I want 跨书会话的"最近活跃"裁决与书级同源(服务器时钟打 updated_at), so that 排序语义全库一致(D-19 精神)。
34. As a developer, I want 新测试全部挂既有 CI job(backend / web E2E), so that 反馈节奏不变、无新 job 维护面(D-23)。

## Implementation Decisions

- **范围口径**:本 spec = S4 全库纯向量多书检索(D-36)+ 跨书会话域(创建入口、路由、列表)+ D-33 悬空引用降级。**§9 三个待定项本轮全部落定(已与用户确认)**:S4 入口 = 书库页全局入口;跨书会话创建 = 提问自动路由(D-32 精神,无显式"新建"按钮);检索范围 = 全库自动,未就绪书静默排除。安卓(M5)、上云(M6)各出各的 spec。
- **模块划分**:
  - 后端 chat 域扩展:跨书受理链路(前置校验 → 跨书会话路由 → 用户消息落库 → 检索式装配 → SSE 中继),复用既有 SSE 中继、消息落库、refs 序列化;书级 S1/S2/S3 链路行为零变化。
  - 后端 embedding 域扩展:向量检索查询由"单书过滤"泛化为"书集合过滤"(集合为空 = 全库),命中携带书标识与书名;就绪书集合的计算复用既有 latest-job 裁决口径。
  - apps/web(扩展):Library 页全局「AI 伴读」入口与跨书会话面板——从既有 AiPanel 抽出可复用的消息流/引用条/输入部分;引用点击跳转经应用顶层状态传递(打开对应书 → 阅读器就绪后执行 S3 同款章 + 摘录定位,未命中停章首)。
  - packages/api-client(扩展):跨书提问/列表端点类型、Citation/ChatRef 增加书字段、书库列表项嵌入就绪摘要;桌面壳零改动。
- **数据迁移:无 schema 变更**。chat_session.book_id 已可空(V4 预留,跨书会话 = book_id 为空的会话);refs/citations 增加字段属数据形状扩展(jsonb,非 DDL)。
- **API 契约**:
  - 跨书提问:新增全局提问端点(书前缀之外的独立路径,具体命名实现定),请求体 = 提问内容 + 可选会话 id(无书 id、无 selection、无 retrieval 标志——跨书提问恒为检索式);响应 SSE 事件序列与书级完全同构(meta → delta… → done/error,citations 随 meta)。
  - 跨书会话列表:新增全局会话列表端点,仅返回 book_id 为空的会话,按最近活跃排序;现有书级列表端点(eq 过滤)天然不含跨书会话,零改动。
  - 消息查看/重命名/删除:复用现有会话级端点(本就不依赖书属)。
  - 书库列表响应扩展嵌入就绪摘要(每书最新任务状态 + 是否就绪),入口显隐与嵌入状态卡同源消费;具体字段形状实现定。
- **引用形状(向后兼容扩展)**:retrieval 类 refs/citations 增加 bookId + bookTitle——**书名在落库时取快照存进 refs**(不靠 join 实时取);S3 书级提问的引用不填这两字段,既有形状不受影响。书删除后:会话与消息原样保留(FK 级联不触及空 book_id,天然成立),引用里的 bookId 悬空,前端据"书不在书库列表"降级为"《书名快照》(原书已删除)"占位并禁用跳转。
- **检索语义**:就绪书集合 = 全部"最新嵌入任务 done 且模型 = 当前 embedding 配置"的书;检索 = 问题向量在集合内 cosine 距离 top-k(k 沿用 S3 取值);**不做每书配额**(纯相关度,配额调优移后续);token 装配复用既有份额贪心与 D-37 计数。prompt 系统说明改为多书语境(不绑定单一书名),检索块溯源头带〔书名·第 N 章〕。
- **前置校验(两态,可读中文文案)**:未配置 embedding / 全库就绪书集合为空。其余未就绪情形(某书未嵌入、模型已换)静默排除,不单独报错——与 S3 书级五态显式报错的口径差异是刻意的:多书场景下逐书报错只会变成噪音。
- **会话路由(D-32 精神)**:显式会话 id → 必须存在且为跨书会话(book_id 为空),否则可读错误;缺省 → 取最近活跃的跨书会话,无则在受理通过后新建(标题 = 首条提问截断,同书级口径)。跨书会话的 updated_at 活跃度刷新与书级同源(新消息/重命名即刷新,D-19 服务器时钟)。
- **入口显隐(FR-403)**:未配置 embedding 或就绪书集合为空 → 全局入口不渲染;判定数据来自书库列表的就绪摘要 + 模型设置,不新增推送/轮询(与 D-44 口径一致,重开面板自然收敛)。
- **CORS 与鉴权**:沿用 M2 全局 CORS 与静态 token 拦截,新端点一律 401 防线;无新运维面。
- **ADR**:无新选型(全为既有决策的延展);若跨书检索的 SQL 泛化出现关键取舍,顺延编号补记。

## Testing Decisions

- **好测试的标准**(沿用 M1–M4):只断言外部可观察行为——HTTP 状态码、响应体(含可读错误文案)、SSE 事件序列、数据库行(会话/消息/refs 形状)、浏览器里可见的结果与持久化效果;不 mock 被测边界内的模块(检索查询、会话路由、SSE 中继都在边界内);唯一被替身的是系统边界外的 embedding/chat 服务,替身打在网络层(OpenAI 兼容 stub,向量确定性)。
- **Seam A(既有扩展,已与用户确认)**:后端 HTTP × Testcontainers(pgvector 容器 M0 起在用)+ OpenAiStubServer /embeddings。覆盖:两本书嵌入完成 → 跨书提问 → SSE 序列正确 + citations 含书身份且随 meta 下发 + refs 落库带书名快照;发给 chat stub 的 prompt 含多书块与〔书名·第 N 章〕溯源头(stub 确定性向量使命中跨两书可断言);续问(带/不带会话 id)落入同一跨书会话;显式会话 id 指向书级会话 → 可读错误;跨书会话列表只含跨书会话;删一本书 → 跨书会话与消息仍在、refs 原样(D-33);前置两态(未配置 / 全库无就绪书)可读错误;只嵌一本书时检索只命中该书(未就绪书静默排除);模型已换的书被排除;重命名/删除跨书会话;书级 S1/S2/S3 回归不变;新端点 401。**Prior art**:RetrievalAskIntegrationTest、ChatAskIntegrationTest、OpenAiStubServer、IntegrationTestBase。
- **Seam B(既有扩展,已与用户确认)**:Playwright 全栈 E2E,harness stub-llm(含 /embeddings)。覆盖:未配置 embedding → 无全局入口;配置 + 两本书嵌入完成 → 入口出现 → 跨书提问 → 流式回复 + 引用条(流式开始前可见)→ 点击"另一本书"的引用 → 打开该书阅读器并定位章节摘录 → 刷新后引用仍在;删除其中一本书 → 重开跨书会话 → 该书引用显示"原书已删除"占位且不可点;会话重命名/删除;书级 AI 面板回归(跨书会话不出现在书级列表)。**Prior art**:s3-citation.spec.ts、embedding.spec.ts、ai-chat.spec.ts、stub-llm.ts、resetBackend。
- **纯函数:无新增缝**(预算计算器与切块器不动,跨书装配复用既有口径)。
- **真实 embedding(bge-m3):人工验收清单**——真实跨书问句("A 书与 B 书怎么看 X")的多书命中与对比质量;真实删书后的占位渲染。对应 M4 验收记录留办的决策输入闭环。
- **packages/api-client**:无独立单测(沿用既有口径,经 Seam A 契约与 Seam B 链路间接覆盖);桌面壳无自动化(零逻辑,人工烟测)。

## Out of Scope

- 检索范围勾选书单 / 会话固定书单(v2 候选;§9 本轮定全库自动,已与用户确认)。
- 关键词/多路召回、中文分词(D-36 明确移 v2)。
- 每书命中配额、跨书结果多样性/去重策略调优。
- ANN 索引(HNSW/IVFFlat)——沿用顺序扫描,M4 ADR-0008 已论证个人量级达标。
- S1/S2/S3 行为变化(书级链路零改动;共享代码抽取以不改变外部行为为准)。
- 阅读器内的跨书入口(v2 候选,依真实使用体验再议,见 Further Notes)。
- 划线进上下文(D-42 v2)、对话摘要、多模型 profile(v2)。
- 安卓端一切(M5)、上云与 HTTPS(M6)。
- 桌面壳特有增强(沿用 M2/M3/M4 spec 口径)。

## Further Notes

- **M4 验收映射**:S4 为 M4 可选项,本 spec 兑现 D-36(纯向量多书检索)与 D-33(跨书会话不级联 + 引用降级占位)两笔欠账;M4 spec · Out of Scope 中"跨书 refs 降级渲染"即本件。
- **§9 待定项闭环**:三项全部落定(本轮与用户确认)——S4 会话入口与跨书会话创建入口 = 书库页全局入口 + 提问自动路由;S4 检索范围 = 全库自动。需求文档 §9 该行可销。
- **决策输入声明**:M4 验收记录人工清单第 3 项(真实 embedding 检索质量)本应作为入口形态输入;本轮按 stub 全链路体验与架构顺延性定了书库页入口。真实使用后若发现对比提问高频发生在阅读中,再评估阅读器内入口(v2,已在 Out of Scope)。
- **跨书引用跳转精度**沿用 S3 口径:章 + 摘录定位,未命中停章首,不承诺 CFI 级(D-40 清洗口径决定)。
- **refs 存书名快照而非实时 join**:书删除后引用仍可读、前端零额外查询——D-33 的最小实现路径;悬空 chapterId/bookId 与 S3 refs 既有行为一致。
- **跨书就绪 = 逐书 latest-job 裁决的集合化**,与 S3"该书嵌入完成"同一裁决函数,全库就绪度无独立状态机。

# ADR-0008:向量维度不带 typmod + 个人量级顺序 cosine 扫描

- 状态:已接受(M4-02)
- 日期:2026-08-29
- 关联:需求文档 §5.1(性能)、§6.4(数据模型)、R-3(维度陷阱)、D-36(检索策略)、M4 spec · Implementation Decisions

## 背景

M4 落地向量检索:`document_chunk.embedding` 用 pgvector 存储,需定两件事——
列要不要固定维度(typmod),以及检索走什么策略(顺序扫描 vs ANN 索引)。

## 决策

1. **embedding 列 `vector` 不带 typmod**(不写 `vector(1024)` 之类):
   - 同一本书的全部块由**同一模型一次任务**嵌入,维度天然一致,无需库级约束;
   - 换嵌入模型(维度可能变)= 清该书旧块全量重嵌,不产生同列混维度;
   - 查询向量与块向量同模型由 S3 前置校验保证("该书嵌入完成" = 最新 job done 且
     job.model = 当前配置 embedding_model);不同维度的比较在 PG 层天然报错,不额外防御。
2. **检索 = 按 book_id 过滤 + 顺序 cosine 距离扫描取 top-k**(`ORDER BY embedding <=> q LIMIT k`),
   HNSW/IVFFlat ANN 索引**不进 M4**:
   - 个人量级:几百本 × 几百块/本 ≈ 几万块,单书过滤后的候选集只有几百;
     顺序扫描 P95 < 500ms 远低于需求 §5.1 的感知阈值;
   - ANN 索引带来构建/维护成本与调参面(ef_search、lists),当前量级无收益;
   - 列入后续优化候选:块量或书量增长两个数量级再评。
3. **距离用 cosine**:bge-m3 类中文 embedding 模型的语义相似度以余弦为准,与上游归一化口径一致。

## 后果

- 换模型重嵌入是全量操作(清旧块),个人量级秒级完成,可接受;
- 不同维度向量误比较会得到 PG 报错而非静默错排——由前置校验挡在入口;
- 未建 ANN 索引前,检索性能随单书块数线性;上线后以真实数据观测,必要时按本 ADR 的
  量级阈值触发索引评估。

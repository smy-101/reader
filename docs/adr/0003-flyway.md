# ADR-0003: schema 迁移统一走 Flyway,禁止手改

- 状态:已接受(2026-02,盘问 R5-Q7)
- 关联决策:D-17(需求文档 §6.1)

## 背景

项目有开发(`reader_dev`)与生产(`reader`)两个云库(D-11),且 schema 会随里程碑持续生长(M0 两张表 → 划线/进度 → 会话/向量块 → 向量列)。若无版本化迁移机制,两库结构漂移只是时间问题。

## 决策

**Flyway** 管理 PostgreSQL schema:`backend/src/main/resources/db/migration/` 下按 `V<n>__描述.sql` 递增;建表、改表、加 `vector` 列一律走迁移脚本,**禁止手工改库**。

## 理由

- 迁移即版本历史:schema 变更有据可查、可回溯,毕业标准的"过程纪律"落在实处(D-16)。
- Spring Boot 原生集成,应用启动自动对齐库结构,开发/生产/测试(Testcontainers)三处同源。
- 拒绝 JPA `ddl-auto` 自动建表:无版本、不可回溯,升级即赌博;手写 psql 脚本则不可重复执行。

## 后果

- 任何 schema 需求(哪怕加一列)都要新开一个迁移文件;文件只增不改(已应用的迁移改了会校验失败)。
- 测试容器每次全新建库,迁移全量重放——这同时是对迁移幂等性的持续验证。

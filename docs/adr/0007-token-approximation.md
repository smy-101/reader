# ADR-0007: token 计数用字符近似启发式,不引 tokenizer

- 状态:已接受(2026-08,M3)
- 关联决策:D-37(需求文档 §6.2,盘问 R8-Q10)、D-27(上下文上限可空 = 8k 保守);关联需求 FR-302(上下文预算策略)

## 背景

S2 当前书问答需要在发送前装配 prompt:书内容优先占额、剩余装最近对话、装不下按 整书 → 目标章 → 检索式 降级。降级裁决依赖 token 计数。备选:接入真实 tokenizer(BPE,如 tiktoken 的 Java 移植)、或按字符近似估算。

## 决策

**字符近似启发式**(`TokenEstimator`,纯函数):中文口径字符(CJK 统一表意/扩展、CJK 标点、全角形式、假名)≈ 1 token/字,其余字符 ≈ 1 token/4 字符,两组分别累计求和、向上取整。方向性原则:**宁可高估、提前降级**——把预算算得比实际紧,最坏结果是过早降级到目标章/断尾,而不是把小上下文模型撑爆。

## 理由

- **口径稳定可依赖**:预算策略是产品行为(降级/断尾文案要给用户看),近似计数是确定性的、与模型无关的;同一本书在不同模型配置下降级行为只随配置变,不随 tokenizer 版本变,可单测钉死(M3 验收标准原文)。
- **成本**:tokenizer 依赖引入 ~MB 级词表与维护面,且不同模型(DeepSeek/Qwen/GLM)各自 tokenizer 结果本就不同,"精确"对单一模型才成立;近似口径对所有 OpenAI 兼容服务一视同仁(FR-402 的适配面)。
- **误差有界且方向安全**:中文为主的书按 1 token/字对主流中文模型普遍略高估(DeepSeek/Qwen 中文约 0.6-0.7 token/字);英文 4 字符/token 对 BPE 也偏高。高估 → 提前降级 → 行为保守,正是 FR-302 要的方向。上下文上限未填时再叠一层 8k 保守缺省(D-27),双重保守。
- **量级**:个人书库(单本书几万到几十万 token),不追求逐 token 精确;预算只决定装什么,不决定计费。

## 后果

- 极端文本(代码密集/罕见语种)下可能高估 2 倍以上,导致本可装整书时降级到目标章——体验损失,不是正确性损失;可在降级文案中如实告知用户"约 N token"。
- 若未来接计费或硬性窗口约束(上云/M6),再评估换真实 tokenizer;本 ADR 只约定 M3 起的预算裁决口径。
- 近似规则如有调整,以 `TokenEstimator` 单测为准绳同步更新本 ADR。

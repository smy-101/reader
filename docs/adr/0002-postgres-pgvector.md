# ADR-0002: 数据库选 PostgreSQL + pgvector,单库管业务与向量

- 状态:已接受(2026-02,盘问 R2-Q10)
- 关联决策:D-10(需求文档 §6.1);关联场景:S3/S4(§4.3)、§5.1 性能量级

## 背景

AI 伴读的 S3(定位原文)与 S4(跨书对比)需要向量检索(embedding + 相似度查询);书库、划线、会话等业务数据也需要一个持久库。备选有两条路:业务库 + 独立向量库(Milvus/Qdrant 等),或单库带向量扩展。

## 决策

**PostgreSQL 18 + pgvector 扩展**,业务表与向量列(`document_chunk.embedding`)同库;云 ECS 自建容器 `pgvector/pgvector:pg18`(部署细节见 D-14/D-20,实例记录见需求文档 §10)。

## 理由

- **个人量级单库足够**:几百本书、几万向量块,pgvector 的 cosine 检索 P95 < 500ms 轻松达标(§5.1),独立向量库的运维成本远超收益。
- **单库带来事务一致性**:删书级联清向量、嵌入任务与业务状态同库演进,不需要跨库对账。
- 已有 ECS 与自建 PG 经验,复用现有机器(D-20)。

## 后果

- 向量维度绑定 embedding 模型(如 bge-m3=1024);换模型 = 改列维度 + 全量重嵌入,已接受(R-3,量级可忽略)。
- 中文关键词检索在 PG 上缺好用分词,S4 定为纯向量召回、多路召回移 v2(D-36),避开自建 zhparser 镜像。

## 1. 背景与目标

做一个**个人 AI 阅读器**:把读的书加入 AI 上下文,边读边讨论;桌面端 + 安卓端;后端用 Java,顺带完成"工作常用框架"的实践目标。

三重目标,冲突时按此优先级裁决:

1. **学习优先**(Java/Spring 工作框架实践是第一目标)
2. **产品可用**(自己日常真的用它读书)
3. **功能完整**(AI 四场景全做完是理想,不是承诺)

**毕业标准(验收线)**:
- 过程纪律:每个里程碑配 JUnit 5 + Testcontainers 测试交付,关键选型写简短 ADR,CI(D-23)保底
- 最终验收:M6 结束时能**不查教程**从零搭一个新 Spring Boot 服务(CRUD + 测试 + 部署)
- "能读懂业务代码"(DI、事务、分层、常用注解能说清为什么)作为自然结果,不单独验收

## 3. 范围

### 3.1 做(In Scope)

| 模块 | 内容 |
|---|---|
| 书源 | **仅 EPUB + 本地文件导入**(上传入口仅 Web/桌面,见 §3.3);文件只存服务端,端上按需下载 |
| 阅读 | 网页渲染(**foliate-js**,D-18)、阅读进度、划线笔记 |
| 同步 | 书库元数据 + 进度 + 划线跨设备同步;安卓本地缓存副本 |
| AI 伴读 | 四个场景(见 4.3),分阶段交付;回复 SSE 流式(D-25) |
| 模型接入 | 用户自定义 API(OpenAI 兼容协议),自身不提供 AI 服务 |

### 3.2 不做(Out of Scope)

- **MOBI**(死格式);**在线书源/爬虫**(版权与工程量);**DRM 加密 EPUB**(不支持导入、不做解密,D-29)
- TXT(第二期)、PDF(第三期,且第一版只做整页渲染、不参与 AI 切块)
- 账号系统、多租户
- 离线划线队列(v2 再做;v1 断网可读、划线在线、进度离线留存联网补报,见 FR-204/D-35)
- 同步冲突的人机合并界面(一律 LWW 后写胜,见 5.3)
- 自建 AI 服务、模型代理网关
- 书内全文搜索(v2 候选);划线/笔记导出(v2 候选)
- 书籍元数据编辑(不做)
- 多模型 profile(v2;v1 单套配置,见 FR-401)
- 划线作为 AI 上下文输入(v2 候选;S2 预算只装书内容 + 最近对话,D-42)
- 阅读设置(字号/主题)跨端同步(仅存本地,见 FR-201)

## 4. 功能需求

### 4.1 书库管理

- FR-101 上传 EPUB(入口仅 Web/桌面)→ 后端**同步**解析(元数据/章节目录/**章节纯文本**/封面,正文入 `chapter.content`,D-26;不做异步任务,D-41)→ 入库 → 原文件落盘;**先解析后落盘(D-29)**:解析失败 → 400 + 可读文案(区分"文件损坏"与"疑似 DRM 保护"),不建 book 记录、不落盘;**纯文本清洗口径(D-40)**:丢图、表格拍平为文本、脚注并入章末、代码块原样保留(细则 M0 解析 spike 定);**批量上传(D-43)**:前端多选循环调单文件接口,后端不变,M1 交付
- FR-102 文件去重(file hash);同 hash 重复上传**幂等**(D-30):200 返回已存在书籍,前端提示"已在书库"
- FR-103 书库列表:封面、标题、作者、阅读进度百分比
- FR-104 删除书籍:连同文件、划线、向量、**该书会话**(前端确认弹窗明示级联范围;跨书会话不受级联影响,其 refs 渲染降级为"原书已删除"占位,D-33)
- FR-105 上传大小上限 100MB,超限返回 413;v1 不做分片/断点上传
- FR-106 书库列表按标题/作者即时过滤(纯前端,几百本量级)

### 4.2 阅读器

- FR-201 浏览器内渲染 EPUB(foliate-js),目录导航、字号/主题基本设置(**设置仅存本地 localStorage,不跨端同步**)
- FR-202 划线(选中文字 → 高亮/颜色/备注),以 EPUB CFI 定位
- FR-203 阅读进度自动上报,跨端接续
- FR-204 安卓端:打开书籍即下载完整副本到本地,离线可读;划线需在线;**进度离线留存,联网后自动补报一次单条 upsert(D-35,不做队列)**
- FR-205 安卓书库支持**删除本地副本**(下次打开重新下载;按 file_hash 复用书源文件缓存)
- FR-206 书库列表以服务端为准:同步发现书籍已被删除 → 端上自动清本地副本并移出书架,无需用户操作(D-34)

### 4.3 AI 伴读(核心价值,四场景按序交付)

| # | 场景 | 说明 | 依赖 | 里程碑 |
|---|---|---|---|---|
| S1 | 选中即问 | 划一段问"这段什么意思",仅传该段文字 | 无 | M3 |
| S2 | 当前书问答 | "总结第 5 章方法论":按上下文预算自动决定塞整书/整章/降级,预算链见 FR-302 | context 上限配置(FR-401) | M3 |
| S3 | 定位原文 | "作者在哪讨论过 X?"→ 检索 + 跳转到原文位置 | **embedding + pgvector** | M4 |
| S4 | 跨书对比 | 多书**纯向量**检索、对比观点;关键词/多路召回移 v2 候选(D-36,避开中文分词扩展自建镜像) | S3 | M4(可选) |

- FR-301 对话按会话组织,消息记录引用的书籍/章节/划线来源;**S1 与 S2 走同一消息通路**(D-32):S1 提问自动落入该书最近活跃会话(无则新建),选中文字作为该条消息的引用
- FR-302 **上下文预算策略**(纯函数,可单测):预算分配 = 书内容优先占预算 → 剩余装最近对话消息(装不下丢最旧,**不做摘要**);书内容塞不下时按链降级:**整书 → 目标章 → 检索式(需 embedding)**;未配 embedding 且单章超限 → 返回明确文案("上下文不足,请换大上下文模型或配置 embedding"),优雅报错不炸;context 上限未填(未知)按保守 **8k** 计。不写死任何模型假设。**目标章来源(D-31)**:提问请求携带可选 chapter_id/CFI,默认由前端填当前阅读位置,显式点名章节用显式值,不依赖 reading_progress 反查。**token 计数(D-37)**:字符近似启发式(中文 ≈ 1 token/字,英文 ≈ 1 token/4 字符,向上取整,宁可提前降级),不引 tokenizer 依赖,M3 以 ADR 记录取舍;**划线不纳入上下文**(D-42:书内容 + 最近对话之外不再叠变量,划线进上下文移 v2 候选)
- FR-303 AI 回复 **SSE 流式**输出;错误/中断以事件类型显式下发,前端不悬挂
- FR-304 会话可删除、可重命名;书删除时级联删该书会话(见 FR-104)

### 4.4 模型设置域

- FR-401 配置 **5+2 项**(D-28):base URL、API key、chat 模型、**上下文上限(可空,空=按 8k 保守)**、embedding 模型(可选)+ **embedding_base_url / embedding_api_key(均可空,空=跟随 chat;允许 chat 与 embedding 各用一家,如 DeepSeek + bge-m3)**;v1 **单套配置**(id 恒为 1),多 profile 放 v2;embedding 模型推荐 **bge-m3**(仅作设置页 placeholder 提示,不写死,R9-Q5)
- FR-402 仅适配 **OpenAI 兼容协议**(覆盖 DeepSeek/Qwen/GLM/Kimi/OpenAI/Ollama);代码留 Adapter 接口,不做 Anthropic/Google 原生协议
- FR-403 embedding 未配置 → S3/S4 入口隐藏,产品优雅降级,不报错
- FR-404 API key 明文存库、设置页**明文回显**(个人工具,已接受;见风险 R-2)
- FR-405 设置页"**测试连接**"按钮:后端分别代理 chat 与 embedding 的最小请求(如 `/models`;embedding 已配置才测),各自返回 ok / 可读错误(配错 base URL 不必等到提问才发现)

## 5. 非功能需求

### 5.1 性能
- 书库量级按几百本、chunk 数按几万条设计;向量检索 P95 < 500ms(该量级下 pgvector 轻松达标)

### 5.2 安全姿态
- 单用户静态 token;**M6 上云维持 HTTP + IP:端口(无域名,D-21),token 为唯一防线,R-8 已接受**;后续购域名备案后可升 HTTPS,不改架构
- **已接受**:开发期云 PG 弱安全(弱密码/公网/无 SSL)——实例定性为测试库

### 5.3 同步策略
- 划线/进度冲突一律 **LWW(后写胜)**,不做合并 UI;裁决时钟 = **服务器统一打 `updated_at`(D-19),客户端不传时间戳**(v1 划线必须在线,无补写历史场景;v2 离线队列再议客户端时钟)
- 拉取策略(D-24):v1 **全量**——打开书拉取该书全部划线 + 单行进度;上报走单条 upsert;不做增量协议;双端同开同一本书时,另一端的划线/进度**重开该书才可见**(无推送/轮询,D-44,已接受)

### 5.4 运维
- 后期上云:Docker Compose 一键部署(ECS 同机,D-20);CI 见 D-23;不配 CD(部署手动,配合 M6 学习)
- 备份 = `pg_dump` **+ 书文件/封面目录打包同步 OSS**(D-20 附带决议);脚本随 M6 交付,含恢复演练

### 6.4 数据模型草图(初稿,M0 落地时细化)

```
book              书籍:id, title, author, language, cover_path, file_hash(唯一), file_size, created_at, updated_at
chapter           章节:id, book_id, seq, title, href, content(纯文本,D-26;清洗口径 D-40), text_length —— 仅"有正文的内容文件"平铺入库,嵌套目录不入库(D-40)
highlight         划线:id, book_id, cfi, text, note, color, created_at, updated_at(LWW 裁决字段,服务器时钟), device
reading_progress  进度:book_id(唯一), cfi, percent, updated_at(LWW,服务器时钟)
chat_session      会话:id, book_id(可空,跨书会话不随书级联删,refs 降级见 D-33/FR-104), title, created_at(删除/重命名见 FR-304)
chat_message      消息:id, session_id, role, content, refs(jsonb:引用的 chunk/划线), created_at
model_settings    模型配置:base_url, api_key, chat_model, chat_context_tokens(可空), embedding_model(可空), embedding_base_url(可空=跟随), embedding_api_key(可空=跟随);单套,id 恒为 1(D-27/D-28)
document_chunk    向量块(M4):id, book_id, chapter_id, seq, content, token_count, embedding vector(N)
embedding_job     嵌入任务(M4):id, book_id, model, status(pending/running/done/failed), chunk_done, chunk_total, error, created_at, updated_at
```

> ⚠ **embedding 维度陷阱**:向量列维度与 embedding 模型绑定(bge-m3=1024,OpenAI=1536…)。策略:建列维度跟随当前配置,**换 embedding 模型 = 全量重嵌入**(个人书库量级,重嵌入成本可忽略,已在 M4 验收项中)。

> 嵌入时机(M4):配置了 embedding → 上传后**后台异步自动嵌入**(embedding_job 记录状态,失败可重试);未配置 → 跳过;换模型全量重嵌入 = **手动触发**入口;S3 以"该书嵌入完成"为可用前置。
